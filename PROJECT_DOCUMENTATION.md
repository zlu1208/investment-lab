## Project Overview


```
├── globals.css          # Global styles and CSS variables
```

| Setting | Value | Purpose |
|---------|-------|---------|

- `skipLibCheck: true` speeds up compilation

## Next.js App Router

### What is the App Router?

A **file-based routing system** where your folder structure automatically becomes URL routes.

### How It Works

**File to Route Mapping:**

```
app/
├── page.tsx                    → GET /
├── layout.tsx                  → Wraps all routes
├── about/
│   └── page.tsx               → GET /about
├── blog/
│   ├── page.tsx               → GET /blog
│   ├── layout.tsx             → Wraps blog pages
│   └── [id]/
│       └── page.tsx           → GET /blog/123, /blog/456 (dynamic)
├── api/
│   └── hello/
│       └── route.ts           → POST /api/hello (API route)
└── dashboard/
    ├── layout.tsx             → Wraps dashboard pages
    ├── settings/
    │   └── page.tsx           → GET /dashboard/settings
    └── profile/
        └── page.tsx           → GET /dashboard/profile
```

### Special Files

| File | Purpose |
|------|---------|
| `page.tsx` | Page component (renders the route) |
| `layout.tsx` | Wrapper component (applies to all child routes) |
| `route.ts/js` | API endpoint handler |
| `loading.tsx` | Suspense boundary UI while loading |
| `error.tsx` | Error boundary for error handling |
| `not-found.tsx` | 404 page |

### Server vs Client Components

**By Default: Server Components**
```tsx
// app/page.tsx - runs on server
export default function Home() {
  // Can access databases, secrets, etc.
  return <div>Hello</div>
}
```

**Opt-in: Client Components**
```tsx
// app/dashboard/page.tsx
"use client"  // Enable browser interactivity

import { useState } from 'react'

export default function Dashboard() {
  const [count, setCount] = useState(0)  // Works now!
  return <button onClick={() => setCount(count + 1)}>{count}</button>
}
```

### In This Project

```
app/
├── layout.tsx          (Root layout - HTML structure, fonts)
├── globals.css         (Tailwind imports + CSS variables)
└── page.tsx            (Homepage template)
```

**Current Routes:**
- `/` → `app/page.tsx` wrapped by `app/layout.tsx`

## Tailwind CSS

### What is Tailwind?

A **utility-first CSS framework**. Instead of writing custom CSS, you compose predefined classes.

### How It Works

**Traditional CSS Approach:**
```css
.button {
  display: flex;
  align-items: center;
  padding: 12px 16px;
  background-color: #000;
  border-radius: 9999px;
}
```

**Tailwind Approach:**
```tsx
<button className="flex items-center px-4 py-3 bg-black rounded-full">
  Click me
</button>
```

### Key Utilities Used in This Project

#### Layout & Flexbox
```
flex              - display: flex
flex-col          - flex-direction: column
items-center      - align-items: center
justify-center    - justify-content: center
justify-between   - justify-content: space-between
```

#### Spacing (Padding & Margin)
```
p-4               - padding: 1rem
py-32             - padding-top/bottom: 8rem
px-16             - padding-left/right: 4rem
gap-6             - gap: 1.5rem (for flex)
```

#### Colors
```
bg-white          - background: white
bg-black          - background: black
bg-zinc-50        - background: very light gray
text-black        - color: black
text-zinc-600     - color: medium gray
```

#### Dark Mode
```
dark:bg-black     - On dark mode: background black
dark:text-white   - On dark mode: text white
```

#### Text & Typography
```
text-3xl          - font-size: 1.875rem
font-semibold     - font-weight: 600
leading-10        - line-height: 2.5rem
tracking-tight    - letter-spacing: -0.025em
```

#### Responsive Design (Mobile-First)
```
sm:items-start    - On small screens and up: align-items start
md:w-[158px]      - On medium screens and up: width 158px
```

#### Interactions & Effects
```
rounded-full      - border-radius: 9999px
transition-colors - CSS transition for colors
hover:bg-[#...]   - On hover: background color
```

### Configuration: `globals.css`

```css
@import "tailwindcss";  /* Import Tailwind framework */

:root {
  --background: #ffffff;
  --foreground: #171717;
}

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --font-sans: var(--font-geist-sans);
  --font-mono: var(--font-geist-mono);
}

@media (prefers-color-scheme: dark) {
  :root {
    --background: #0a0a0a;
    --foreground: #ededed;
  }
}
```

**What this does:**
1. Imports Tailwind CSS framework
2. Defines CSS variables for light/dark modes
3. Injects custom fonts from Next.js
4. Enables automatic dark mode detection

### Responsive Design Pattern

Tailwind uses **mobile-first breakpoints**:

```tsx
<div className="
  w-full           // Mobile: full width
  sm:w-1/2         // Small screens+: 50% width
  md:w-1/3         // Medium screens+: 33% width
  lg:w-1/4         // Large screens+: 25% width
">
  Content
</div>
```

### Component Patterns

#### 1. Root Layout (Server Component)
```tsx
// app/layout.tsx
import type { Metadata } from "next";
import "./globals.css";

export const metadata: Metadata = {
  title: "Investment Lab",
  description: "Your app description",
};

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
```

**Purpose:**
- Wraps entire application
- Exports `metadata` for SEO
- Applies global styles
- Renders `{children}` (child pages/layouts)

#### 2. Page Component (Server Component)
```tsx
// app/page.tsx
export default function Home() {
  return (
    <main>
      <h1>Welcome</h1>
      <p>This is the homepage</p>
    </main>
  );
}
```

#### 3. Feature Layout (Server Component)
```tsx
// app/dashboard/layout.tsx
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <div className="flex">
      <aside className="w-64 bg-gray-100">Sidebar</aside>
      <main className="flex-1">{children}</main>
    </div>
  );
}
```

#### 4. Reusable Component (Client Component)
```tsx
// app/components/Button.tsx
"use client"

import React from "react";

interface ButtonProps {
  onClick: () => void;
  children: React.ReactNode;
}

export default function Button({ onClick, children }: ButtonProps) {
  return (
    <button
      onClick={onClick}
      className="px-4 py-2 bg-blue-500 text-white rounded hover:bg-blue-600"
    >
      {children}
    </button>
  );
}
```

**Key Points:**
- Use `"use client"` only when needed (events, hooks)
- Type props with interfaces
- Use descriptive names
- Apply Tailwind classes directly

### Props Pattern

```tsx
interface ComponentProps {
  title: string;
  children: React.ReactNode;
  onClick?: () => void;  // Optional prop
  isActive?: boolean;
  items: Array<{ id: string; label: string }>;
}

export default function Component({
  title,
  children,
  onClick,
  isActive = false,
  items,
}: ComponentProps) {
  return <div>{title}</div>;
}
```

## Best Practices

1. **Use Server Components by Default**
   - Fetch data on the server
   - Add `"use client"` only when you need interactivity

2. **Type Everything**
   - Use TypeScript types for all props
   - Enable `strict: true` in tsconfig

3. **Organize by Feature**
   - Group related components in folders
   - Keep utilities in `lib/` directory

4. **Responsive First**
   - Write mobile styles first
   - Add larger breakpoints as overrides

5. **Use Tailwind Utilities**
   - Compose classes instead of custom CSS
   - Avoid using `style` prop
   - Extract repeated classes to components

6. **Optimize Images**
   - Use Next.js `<Image>` component
   - Specify `width` and `height`
   - Use `priority` for above-the-fold images

7. **Environment Variables**
   - Public env vars: prefix with `NEXT_PUBLIC_`
   - Private env vars: don't prefix (server-only)
   - Create `.env.local` file
